# 의약품 공식 레퍼런스 생성 도구

병원 약물선정위원회 비교표 검토를 위해 식품의약품안전처 허가사항과 건강보험심사평가원 급여약가를 통합 조회하는 Streamlit 도구입니다. 신청의약품과 비교의약품을 여러 함량 품목으로 구성하는 선택형 그룹 관리, 기준일 약가 판정, AI 검토용 JSON 출력을 제공합니다.

## 🆕 v4.8.1 업데이트 (2026-11-04)

- **일반의약품의 금기사항·보관 및 취급상의 주의사항 찾기**
  - 일반의약품은 소제목이 전문의약품과 달라 빈칸으로 나왔습니다(예: 타이레놀정500밀리그람). 다음 두 항목만 찾는 말을 추가했습니다.

    | 항목 | 일반의약품 소제목 예 | 추가한 찾는 말 |
    |---|---|---|
    | 금기사항 | 다음과 같은 사람은 이 약을 복용하지 말 것 | 복용하지 말 것, 사용하지 말 것, 복용(사용)하지 마십시오 |
    | 보관 및 취급상의 주의사항 | 저장상의 주의사항 | 저장상의 주의 |

  - "이 약을 복용하는 동안 다음의 약을 복용하지 말 것"(상호작용 소제목)이 금기사항에 섞이지 않도록, 금기사항에서는 "동안"이 들어간 소제목을 뺍니다(`"!동안"`). 찾는 말 목록에서 `!`로 시작하는 말은 그 말이 든 소제목을 제외한다는 뜻입니다.
  - 신중투여·상호작용·이상반응 등 다른 항목의 찾는 말은 바꾸지 않았습니다.
  - PDF 글은 소제목 번호가 1, 2, 3… 차례로 이어져야 소제목으로 인정합니다. 일반의약품의 중간 소제목("복용하기 전에", "즉각 중지" 등)은 `SECTION_HEADING_HINTS`로 **소제목 경계만** 알아보게 했습니다. 이 표현들은 어느 결과 항목에도 들어가지 않으며, 이 처리가 없으면 그 뒤의 "저장상의 주의사항"을 놓칩니다.
  - 이전에 빈칸으로 저장된 항목은 다음 조회 때 캐시에 저장된 원문에서 다시 찾으므로 API를 다시 부르지 않습니다.

  - 파일 위치: app.py와 같은 폴더(이름에 `비급여` 포함) 또는 `data/비급여목록/` 폴더. 여러 개면 파일 이름이 가장 뒤인 것(날짜가 가장 최근인 것)을 씁니다. 새 목록이 나오면 `20261201_비급여목록.xlsx`처럼 날짜로 시작하는 이름으로 올리세요.
  - 사이드바에 지금 쓰는 목록 파일 이름이 표시됩니다.

## v4.7.1 업데이트 (2026-11-04)

- **낱알이 아닌 비급여 약(주사제·연고·액제 등)의 약효분류 찾기 개선**
  - 심평원 성분약효 API를 성분명으로 찾을 때, `원료약품 및 분량`의 `성분정보`(예: `덱사메타손(으)로서 5 밀리그램`)에서 기준 성분명을 뽑아 먼저 검색합니다. 염 이름이 달라도 찾을 수 있습니다.
  - 검색 결과 중 일반명이 검색어로 **시작하는** 항목만 남깁니다(예: `프레드니솔론` 검색에 `메틸프레드니솔론`이 섞이지 않게).
  - 같은 성분이라도 제형마다 분류가 다르므로, 제품명(필요하면 성상)으로 투여경로(내복·주사·외용)를 추정해 같은 경로 항목만 남깁니다. 그래도 여러 분류가 남으면 제품명의 제형(점안·연고 등)과 심평원 제형구분명으로 한 번 더 좁힙니다.
  - 끝까지 분류가 하나로 모이지 않으면 비워 두고, `API 경고/오류`에 후보 분류를 남깁니다.

## v4.7.0 업데이트 (2026-11-04)

- **비급여 약의 약효분류·성분 정보 채우기**
  - 약효분류번호·일반명코드는 심평원 약가(급여) 목록에서 가져오기 때문에, 급여 약가가 없는 비급여 약은 빈칸이었습니다. 이제 다음 순서로 채웁니다.
  - 약효분류·분류명: ① 심평원 약가 → ② 식약처 **의약품 낱알식별 정보**의 `CLASS_NO`·`CLASS_NAME`(예: `01190` → `119`, `기타의 중추신경용약`) → ③ 심평원 성분약효 API를 성분명(한글·영문)으로 조회해 분류가 하나로 모일 때만 사용
  - 일반명·함량내용·단위: ① 심평원 성분약효(일반명코드) → ② 식약처 `원료약품 및 분량`(MATERIAL_NAME). 복합제는 성분별로 줄을 나눠 표시하고, `성분정보`(예: 발베나진(으)로서 40 밀리그램)가 있으면 함량 옆 괄호에 적습니다.
  - 어디서 가져온 값인지 `분류출처`, `성분출처` 열에 표시합니다.
  - 낱알식별 정보는 기존 `MFDS_KEY`를 사용하며, 공공데이터포털에서 **식품의약품안전처_의약품 낱알식별 정보** 활용신청이 필요합니다. 정제·캡슐 등 낱알 의약품만 들어 있어 주사제·외용제 등은 ③으로 넘어갑니다.
  - 낱알식별 API 주소는 `MFDS_PILL_URLS`의 후보(버전 03 → 02 → 01)를 차례로 시도하고, 응답이 온 주소를 기억합니다. 결과는 `cache_낱알분류.json`에 캐시합니다(오류는 캐시하지 않음).
- **AI 검토용 JSON `schema_version` 1.4**: `hira_component`에 `class_source`, `component_source`를 추가했습니다.

## v4.6.2 업데이트 (2026-11-04)

- **검색 속도 개선**
  - 조회를 하면 상세정보 캐시(`cache_상세정보.json`, 문서 원문 포함)가 바뀌고, 그다음 검색 때 이 큰 파일 전체를 다시 읽어 검색 인덱스를 만들었습니다. 조회를 할수록 캐시가 커져 검색이 점점 느려졌습니다.

  - 캐시 JSON을 들여쓰기 없이 저장해 파일 크기와 읽기·쓰기 시간을 줄였습니다.

  - 재배포·재부팅하면 Streamlit Cloud 서버의 캐시 파일이 지워지므로 그때는 처음부터 다시 수집합니다.

## v4.4.1 성분 검색 · 정제된 전체 필드 · 품목별 비교표

- 그룹 기능은 기본적으로 꺼져 있으며, 필요한 경우 화면의 옵션을 켜서 사용합니다.
- 옵션을 끄면 기존처럼 하나의 일반 조회 목록으로 품목을 관리합니다.
- 신청의약품 그룹에 여러 품목을 추가할 수 있습니다.
- 비교의약품 그룹을 필요한 만큼 만들고, 각 그룹에 여러 함량 품목을 추가할 수 있습니다.
- 검색 결과 여러 행을 선택해 원하는 그룹으로 한 번에 이동합니다.
- 그룹 표에서 제품명의 자동 함량 파싱값을 확인하고 직접 수정하거나 품목을 제거합니다.
- 조회 결과, 비교표 CSV, AI 검토용 JSON에 그룹명과 확정 함량이 함께 기록됩니다.
- 그룹 비교표에서는 비교의약품을 먼저 표시하고 신청의약품을 맨 오른쪽에 배치합니다.
- 그룹 옵션은 `1. 의약품 검색` 상단의 `조회 방식` 카드에서 켭니다.
- 사용하지 않는 DUR 엑셀 업로드 및 DUR 결과 탭은 화면에서 제거했습니다.
- 의약품명·제약사명뿐 아니라 성분명과 주성분 영문명으로 검색할 수 있습니다.
- 조회 설정의 `[전체] 식약처 제공 항목`을 켜면 지원 항목과 의미 있는 상세 API 필드를 `MFDS_` 열과 JSON에 포함합니다.
- `EE_DOC_DATA`, `UD_DOC_DATA`, `NB_DOC_DATA` 등 XML 원문과 빈값은 전체 결과에서 제외합니다.
- 비교표는 다시 품목 하나당 한 열로 표시하며 신청의약품은 맨 오른쪽에 배치합니다.
- `RARE_DRUG_YN`은 `희귀의약품`이라는 한글 항목으로 항상 조회 결과에 포함합니다.

## 핵심 원칙

- 허가사항은 식약처 상세 API 원문을 함께 보존합니다.
- 제품 식별은 `BAR_CODE` 4~11번째 8자리와 `mdsCd` 앞 8자리 일치를 우선합니다.
- 약가는 기준일에 유효한 이력 중 적용시작일이 가장 최근인 값을 선택합니다. **(2026-10-19 변경)** 같은 8자리 코드 아래 포장별 제품코드(`mdsCd` 9자리)가 여러 개이면, 제품코드마다 이 규칙을 적용해 모두 표시합니다.
- 코드가 일치하지 않으면 제품명만으로 약가를 확정하지 않습니다.

## 설치 및 실행

```bash
python -m pip install -e .
export MFDS_API_KEY='...'
export HIRA_API_KEY='...'
drug-reference --item-seq 000000000 --as-of 2026-09-21 --output reference.json
```

API 키는 소스나 결과 JSON에 저장하지 않습니다.

## Streamlit 배포

Streamlit Community Cloud의 **Main file path**에는 `app.py`를 지정합니다.
의존성은 저장소 루트의 `requirements.txt`에서 설치됩니다.
배포 설정의 Secrets에 아래 값을 등록합니다.

```toml
MFDS_KEY = "식약처 서비스키"
HIRA_KEY = "심평원 서비스키"
```

로컬 실행은 다음과 같습니다.

```bash
python -m pip install -e .
streamlit run app.py
```

## 출력

출력 JSON은 조회 기준일, 매칭 상태, 식약처 원문/정규화 텍스트, 심평원 현재 약가와 적용기간, 경고를 포함합니다. **(2026-10-19 변경)** 포장별 약가가 여러 개인 품목은 `hira_prices` 목록에 전체 약가가 들어갑니다. 이 JSON과 비교표 또는 PPT를 함께 제공하면 검토 지침에 따라 사실관계를 대조할 수 있습니다.

## 기준일 약가와 검토용 JSON

조회 전에 심평원 약가 기준일을 선택합니다. 앱은 `adtStaDd ≤ 기준일 ≤ sellEptDd`인 이력 중 적용 시작일이 가장 최근인 약가를 선택하며, 종료일이 비어 있으면 계속 유효한 것으로 처리합니다. 조회 후 `AI 검토용 JSON 다운로드`를 눌러 비교표 또는 PPT와 함께 사용할 공식 레퍼런스를 저장할 수 있습니다.
